# 최근 작업순 워크스페이스와 최신 요청 제목

별도 최근 5건 패널 대신 기존 워크스페이스 목록을 최근 작업순으로 표시한다. 앱 입력창에서 요청을 전송하거나 서버가 새 완료 이벤트를 확인하면 해당 워크스페이스가 위로 이동한다. 단순 열람, 출력 스트리밍, 입력 대기 상태 변화, 완료 확인, 재접속은 순서를 바꾸지 않는다. 드래그하면 선택한 순서를 유지하다가 이후 새 요청·완료가 발생한 워크스페이스만 다시 위로 이동한다. 드래그 순서는 기존처럼 기기별로 저장하고, 실제 작업 시각은 서버에서 공유한다.

기존 세션 제목은 수동 이름 또는 에이전트가 지정한 tmux pane title이었다. 활성 세션은 약 2초마다, 나머지는 약 1초마다 조회하므로 에이전트가 제목을 바꾸지 않으면 이전 제목이 계속 표시됐다.

이제 Send/Ctrl+Enter의 전송 성공 직후 요청의 첫 번째 비어 있지 않은 줄을 최대 120자로 제목에 반영한다. AI 요약이나 별도 외부 모델 호출을 하지 않는다. 전체 요청·터미널 출력은 새 메타데이터 파일에 저장하지 않는다. 수동 이름을 우선하고, 그다음 최신 요청 제목, 에이전트 제목 순으로 사용한다. 터미널에 직접 타이핑한 입력은 수집하지 않으며, 앱에서 보낸 요청이 없는 세션은 기존 에이전트 제목을 사용한다.

왼쪽 세션 목록, 세션 탭, 뷰어 탭과 격자 제목이 같은 규칙을 사용한다. 성공한 HTTP 응답에도 공유 상태를 포함하므로 보내는 기기는 WebSocket을 기다리지 않는다. 다른 기기는 방송·재접속 상태로 동기화한다. 오래된 HTTP/WS 응답은 버전 번호로 무시한다. 이름이나 상태의 갱신은 닫힌 탭을 다시 열지 않는다.

서버 `.session-activity.json`에는 세션별 최신 요청 제목과 워크스페이스별 작업 시각만 유지한다. 파일은 0600 권한으로 원자적으로 저장하고 Git에서 제외한다. 세션의 호스트·tmux 이름·생성 시각으로 식별하므로 재시작 후 숫자 ID가 달라져도 제목을 유지하고, 숫자 ID가 재사용돼도 이전 제목을 물려주지 않는다. 최신 제목은 최근 5건에 제한되지 않는다. 요청 전송 실패는 제목을 변경하지 않고, 메타데이터 저장 실패를 명령 전송 실패로 오인시키지 않는다. 원격 세션은 기존 프로토콜의 전송 성공 판정(원격 에이전트로 전달됨)을 사용한다.

검증: 프런트엔드 200개, 백엔드 192개 테스트 통과(기존 1개 건너뜀), TypeScript 검사와 운영 빌드 통과. 최신 제목·기기 간 상태 공유, 지연 응답, 요청 경합, 재시작·ID 재사용, 닫힌 탭, 드래그 순서와 후속 작업, 실패한 전송·디스크 저장을 검증한다. 실제 브라우저 화면 검증은 포함하지 않는다.

배포는 아직 하지 않았다. 서버의 저장 전 노트북 6개가 남아 있고 그중 원본 파일이 없는 항목도 있어, `backend/release.py`의 재시작 보호 조건을 유지한다. 앞서 비공개 `.releases/recent-work-preflight-*`에 편집본을 JSON 및 각각의 `.ipynb`로 백업했다. 원본을 저장·복원하거나 서버를 재시작하지 않았다. 운영 서버는 이전 버전이며, 노트북 편집본 처리 후 서버와 프런트엔드를 함께 배포해야 한다.
