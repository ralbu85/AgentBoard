# 서버 Chromium 웹 탭

> 데스크톱 설치 앱에는 화면 중계 없이 로컬 Chromium을 직접 표시하는 방식이 추가되었다. 설치·탭 유지·에이전트 제어는 [Desktop 안내](../../desktop/README.md)를 참고한다. 아래 내용은 일반 웹 접속에서 사용하는 기존 서버 브라우저에 해당한다.

기존 iframe 미리보기를 서버에서 실행하는 Chromium으로 교체했다. 상단 `◎ 웹`, 문서·터미널 링크, 기존 웹 탭을 그대로 사용한다.

## 사용법

- 주소창에서 페이지를 열고 실제 페이지 이력으로 뒤로·앞으로 이동한다. 페이지 안에서 이동한 주소와 제목도 탭에 반영된다.
- PC에서는 화면을 클릭하고 키보드로 입력하거나 붙여넣는다. 한글·모바일 입력은 페이지의 입력칸을 먼저 선택한 뒤 하단 입력창에 작성하고 `입력`을 누른다. `↵`는 페이지에 Enter를 보낸다.
- 모바일은 탭으로 클릭하고 손가락으로 스크롤한다. PC에서는 드래그로 텍스트를 선택한 뒤 `복사`를 눌러 복사할 내용을 확인한다.
- `실행 목록`에서 서버의 열린 탭을 확인하고 `이어 열기`로 다른 기기에서도 같은 페이지를 연다. 동시에 보는 기기는 마지막으로 조정한 페이지 크기를 공유한다.
- 웹 페이지의 파일 선택 버튼을 누르면 앱에 파일 선택창이 나타난다. 업로드는 합계 25MB까지다.
- 다운로드 목록에서 `기기에 저장` 또는 `워크스페이스에 저장`을 선택한다. 로컬 워크스페이스의 `browser-downloads` 폴더에 중복되지 않는 이름으로 저장한다. 원격 워크스페이스는 기기에 저장을 이용한다.

## 수명과 메모리

Chromium 한 개를 필요할 때 실행하고, 전체 실행 탭 수를 기본 3개로 제한한다. 워크스페이스는 서로 다른 브라우저 컨텍스트를 사용한다. 상한에 도달하면 실행 목록에서 탭을 종료해야 새 탭을 실행할 수 있다. 기존 페이지를 자동으로 쫓아내지 않는다.

탭·워크스페이스 전환, 앱 새로고침, 연결 끊김에도 서버 페이지는 유지한다. 보는 기기가 없는 페이지는 화면 전송을 중단한다. 웹 페이지의 스크립트 자체는 계속 실행될 수 있다. `종료` 또는 앱의 웹 탭 닫기는 서버 페이지를 해제하며, 마지막 페이지를 닫으면 Chromium 프로세스도 종료한다. 페이지 입력 내용과 아직 저장하지 않은 다운로드는 종료 시 사라진다.

실행 목록의 메모리 값은 서버 하위 Chromium 프로세스 RSS 합계의 근삿값이다. 공유 메모리가 중복 집계될 수 있으며 운영체제의 고유 물리 메모리 사용량과 같지 않다.

쿠키·localStorage·지원되는 IndexedDB 상태는 `.browser-state/profiles`에 워크스페이스별로 저장한다. 브라우저 페이지의 입력 내용·스크롤·sessionStorage·이동 이력 전체를 디스크에 저장하는 것은 아니다. 서버 재시작 후 앱은 마지막 주소로 페이지를 다시 열며 사이트에 따라 재로그인이 필요할 수 있다.

## 설치와 운영

```sh
backend/.venv/bin/python -m pip install -r backend/requirements.txt
backend/.venv/bin/python -m playwright install --with-deps chromium
```

Docker 이미지도 Chromium과 실행 의존성을 설치한다. `AGENTBOARD_BROWSER_TABS`로 실행 탭 상한을 1~10개 범위에서 설정한다. 상태와 다운로드 임시 파일은 `AGENTBOARD_STATE_DIR/.browser-state`에 저장되며 Git에서 제외된다.

제어 API와 화면 WebSocket은 앱 인증을 사용한다. 브라우저 WebSocket은 Origin도 검사하며 공개 CDP 포트를 열지 않는다. Chromium에는 앱 인증 쿠키를 주입하지 않는다. 다운로드가 임의 서버 경로를 선택하거나 기존 파일을 덮어쓰지 않도록 앱이 저장 위치를 정한다. 브라우저는 Playwright 기본 실행 옵션을 사용하므로 서버를 외부 사이트 탐색에 사용할 운영 환경에서는 전용 사용자/컨테이너 격리도 고려해야 한다.

구현은 [Playwright Chromium](https://playwright.dev/python/docs/api/class-browsertype) 및 [Chrome DevTools Protocol 화면 전송](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-startScreencast)을 사용한다. 변경된 화면의 최신 프레임을 최대 초당 5회 전달한다. 문서·개발 화면 조작을 위한 방식이며 오디오 전송, 영상 재생 품질, DRM, 확장 프로그램, 모든 로그인·보안 인증을 보장하지 않는다. 팝업은 별도 창을 유지하지 않고 현재 페이지로 연다. 사이트의 보안 헤더를 제거하지 않는다.

## 검증

```sh
AGENTBOARD_BROWSER_TESTS=1 backend/.venv/bin/python -m pytest backend/tests/test_browser.py -q
```

실제 Chromium으로 삽입 차단 페이지, 한글 입력, 페이지 유지, 실제 이력, 프로필 분리/복원, 탭 상한, 업로드·다운로드·대화상자와 종료 후 프로세스 해제를 검사한다. 인증 누락·외부 Origin 거절과 다운로드 경로·덮어쓰기 방지도 검사한다.

별도 테스트 서버에서 프런트엔드부터 실제 Chromium까지 연결하여 주소·터치·한글 입력·스크롤·파일 전송·앱 새로고침·서로 다른 브라우저 환경의 이어 열기를 확인했다. 기존 에이전트 세션에 테스트 입력은 보내지 않았다.
