# 데스크톱 채팅 단축키 판별 수정

데스크톱 입력창에서도 `메시지 입력 · Enter 줄바꿈`이 표시되고 Ctrl+Enter 전송이 비활성화되는 문제가 있었다. 입력창이 터미널 렌더러의 `(pointer: coarse)` 판별을 그대로 사용해, 터치 포인터가 있는 데스크톱도 모바일 입력으로 처리했다.

입력창의 기기 판별을 렌더러와 분리했다. 모바일 플랫폼 정보와 iPad의 데스크톱 사용자 에이전트 형태를 구분하고, Windows·Linux 터치 PC는 데스크톱 입력으로 처리한다. 데스크톱에서만 Ctrl+Enter가 Send와 같은 전송 경로를 사용하며 Enter는 줄바꿈한다. 휴대폰·태블릿은 Enter 줄바꿈과 Send 버튼 전송을 유지한다. 터미널의 출력 렌더러·폭·세션은 변경하지 않는다.

프런트엔드 194개 테스트, TypeScript 검사 및 운영 빌드를 통과했다. 입력창 통합 테스트는 터미널이 모바일 포인터로 판별된 상태에서도 데스크톱 Ctrl+Enter 전송을 검증한다. 기기 판별 테스트 8개를 추가했으며, 기존 한글 조합 보호·중복 전송 차단·여러 줄 전송 검사도 유지했다. 실제 브라우저 테스트에는 터치 데스크톱 프로필과 단축키 전송 검사를 추가하고 모바일 Send 검사의 API 경로를 현재 구현에 맞췄다. 안전한 브라우저 실행 환경이 없어 이 브라우저 검사는 실행하지 않았다.

서버는 최신 해시 자산과 캐시 금지 HTML을 제공하는 것을 확인했다. 이미 열려 있는 화면에는 새로고침이 필요하며, 데스크톱 입력창의 안내 문구는 `메시지 입력 · Ctrl+Enter 전송`이다. 프런트엔드만 배포하며 서버 재시작은 필요하지 않다.
