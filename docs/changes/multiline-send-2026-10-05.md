# 모바일 여러 줄 전송 수정

모바일 입력창의 줄바꿈은 보존됐지만, 여러 줄 Send가 사용하던 tmux 붙여넣기에서 LF가 CR로 바뀌고 붙여넣기 경계도 전달되지 않았다. 첫 줄이 먼저 실행되고 나머지는 별도 입력으로 처리될 수 있었다. `/input` 역시 줄마다 Enter를 보내고 있었다.

## 변경

- Send는 본문 전체를 한 번에 전달한 뒤 마지막에 Enter를 한 번 보낸다. 한글, 빈 줄, 들여쓰기, 마지막 줄바꿈을 보존한다. CRLF/CR은 LF로 정규화한다.
- 여러 줄은 `paste-buffer -p -r`로 전달한다. 줄바꿈을 실행 키로 변환하지 않으며, 터미널 앱이 요청한 bracketed paste 모드를 따른다. 동작 근거: [tmux 공식 매뉴얼](https://man.openbsd.org/tmux#paste-buffer).
- 요청마다 별도 tmux 버퍼를 만들고 stdin으로 본문을 전달한다. 공용 버퍼 충돌과 입력 내용을 담는 임시 파일을 없앴다. 같은 세션의 동시 Send는 붙여넣기와 최종 Enter가 섞이지 않게 순서대로 처리한다.
- 현재 입력창은 한 줄과 여러 줄 모두 `/input`을 사용한다. 기존 입력창의 Send가 사용하는 `/paste`도 같은 전송 동작으로 수정했다.
- tmux 전송 실패나 종료된 세션에는 성공을 반환하지 않는다. 입력창은 실패한 본문과 전송 중 새로 작성한 내용을 유지하며 연속 두 번 탭해도 중복 전송하지 않는다.

## 검증

- 백엔드 183개, 프런트엔드 173개 테스트 통과. 기존 환경 의존 테스트 1개 건너뜀.
- 전용 tmux 소켓의 합성 입력 수신기로 실제 PTY 바이트를 검사했다. 수신 결과는 `붙여넣기 시작 + 전체 본문 + 붙여넣기 끝 + Enter 1회`였다. 긴 한글·이모지·빈 줄, 구버전 Send 경로, 동시 전송, 다른 클립보드 보존, 실패 후 버퍼 정리를 검증했다.
- TypeScript 검사 및 운영 빌드 통과. 실행 중인 사용자 터미널에는 테스트 문장을 입력하지 않았다. 실제 iPhone 브라우저에서의 입력 확인은 포함하지 않는다.
